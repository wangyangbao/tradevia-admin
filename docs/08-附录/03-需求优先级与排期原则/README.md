# 附录C  需求优先级与排期原则

> 来源：《蒙牛菲律宾冰淇淋经销商运营系统 PRD V1.0》附录 C。原文状态为“需求评审稿（待业务方确认）”，本文件按模块整理，未改变业务规则。

[返回文档总目录](../../README.md)

功能点编号中的 P0/P1/P2 仅表达必要性，不构成排期顺序。实际排期须遵循依赖关系：组织架构先于一切，因为权限与数据范围依赖它；商品、仓库、价目表先于库存与订单，因为后者需要前者作为主数据；外勤规则与线路先于移动端拜访，因为计划由线路生成；库存与订单先于对账与报表，因为后者是前者的汇总。

建议的依赖顺序为：组织架构与权限 → 基础数据 → 商品与价格 → 仓库与门店 → 外勤动作与类型 → 线路与计划 → 订单 → 发货与出库 → 收款与对账 → 报表 → 接口与日志。任一环节未完成时，其下游功能只能做界面不能做逻辑，测试也无法构造真实数据，强行并行会造成大量返工。

对于 P1 功能，建议采用“先留接口、后补能力”的策略：例如退货在一期虽未纳入，但订单、出库、应收的数据结构应预留退货单关联字段与冲减逻辑位，二期补充时不需要改动核心表结构。P2 功能则以配置项或报表形式预留，不进入一期开发范围。
