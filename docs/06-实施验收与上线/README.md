# 7  实施、验收与上线

> 来源：《蒙牛菲律宾冰淇淋经销商运营系统 PRD V1.0》第 7 章。原文状态为“需求评审稿（待业务方确认）”，本文件按模块整理，未改变业务规则。

<a id="section-7-1"></a>

## 7.1  实施分期建议

建议按三期推进。一期打通“组织与主数据 + 访销全链路 + 库存 + 对账”，这是业务价值最集中的部分；二期补充车销深化、退货、促销与报表增强；三期对接三方系统与数据分析。分期不是削减范围，而是控制上线风险：一期的核心链路若不稳定，后续所有功能都无从谈起。

**表115  实施分期建议**

| 阶段 | 范围 | 交付标志 | 建议周期 |
| --- | --- | --- | --- |
| 一期 | 组织架构、基础数据、门店、商品与价格、外勤、销售、库存、对账、权限、移动端核心 | 两个经销商试点跑通“拜访—订单—出库—配送—签收—收款—对账”闭环 | 按项目计划确定 |
| 二期 | 车销、退货、促销、报表增强、盘点 | 全部经销商上线，车销与访销并行运行一个完整月度 | 试点验收后启动 |
| 三期 | 订单接口、主数据接口、分析看板、BI 集成 | 接口稳定运行 30 天，对账零漏单 | 二期稳定后启动 |

<a id="section-7-2"></a>

## 7.2  验收标准

验收不以“功能页面存在”为标准，而以“业务闭环跑通、数据准确、异常可处理”为标准。下表为必须逐项验证的验收要点，任一项未通过不得进入正式上线。

**表116  验收要点**

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| AC-01 | 组织与权限 | 按四级组织建齐，经销商数据互不可见，越权访问被拦截并记录日志 |
| AC-02 | 主数据完整性 | 门店必填字段完整率 ≥ 98%，商品与价目表可正常取价 |
| AC-03 | 外勤真实性 | 签到需真实定位，模拟定位被识别；照片水印完整；异常签到进入复核队列 |
| AC-04 | 订单闭环 | 订单从提交到签收全链路状态正确，库存锁定与释放准确，无超卖 |
| AC-05 | 库存准确 | 任意时点可用量 = 账面 − 锁定；盘点差异率 ≤ 1%；批次与效期可追溯 |
| AC-06 | 收款对账 | 当日对账单的期末应收与客户应收明细合计一致，差异可登记并审批 |
| AC-07 | 离线可用 | 断网状态下可完成签到、开单、收款；恢复网络后 5 分钟内自动上传且无重复单据 |
| AC-08 | 性能达标 | 按 5.1 节指标压测通过，峰值场景无超时与数据错乱 |
| AC-09 | 接口稳定 | 接口连续运行 7 天，成功率 ≥ 99.5%，重复请求不产生重复订单 |
| AC-10 | 日志审计 | 六类敏感操作均有日志，日志可按对象检索，不可被修改 |

<a id="section-7-3"></a>

## 7.3  培训与上线支持

上线失败最常见的原因不是系统缺陷，而是一线不会用、不愿用。建议按角色分层培训：业务员培训控制在 60 分钟内，只讲签到、开单、收款三个动作，现场实操通关；管理员培训 2 小时，覆盖主数据、规则配置与异常处理；财务培训 1.5 小时，覆盖收款核销、对账与差异处理。

上线首月设置“双轨期”：系统与手工台账并行，每日核对订单与收款，差异当日查清。双轨期结束后，手工台账仅作为抽查依据。同时建立一线反馈通道，业务员可通过移动端提交问题，问题在 24 小时内响应，高频问题纳入版本迭代。
