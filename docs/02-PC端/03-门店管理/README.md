## 3.3.1  模块概述

门店是经销商业务的终点，也是数据量最大、变更最频繁的主数据。四十余家经销商合计门店数量按每家 200—500 家估算，全系统门店规模在一万至两万家之间，且每年有相当比例的新开与关闭。因此本模块既要支持业务员在移动端快速建档，也要支持管理员在 PC 端批量清洗与审核。

门店管理分为两层：门店分类用于建立分类体系（如按渠道、按门店等级、按连锁归属），客户档案用于维护单个门店的全部业务属性。分类不是标签，它直接参与价格、账期、拜访频次的默认值计算，因此分类必须结构化，不允许用自由文本标签替代。

## 3.3.3  客户（门店）档案

客户列表支持按业务单元、大区、经销商、分类、渠道、状态、负责业务员、线路、关键字组合查询，默认按“最近更新倒序”。列表列包括门店编码、名称、分类、渠道、地址摘要、负责业务员、线路、当前欠款、最近订单日期、状态，行内可直接进入详情或发起拜访。

客户详情页采用分区展示：基本信息、地址与坐标、经营信息、信用与结算、关联关系（线路、业务员、所属连锁）、历史记录（订单、拜访、收款）。详情页顶部固定显示关键状态：客户状态、当前欠款、账期与信用额度使用率，便于管理者一眼判断风险。

**表40  客户（门店）字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 门店编码 | 文本 | 是 | 全局唯一，规则 CU-{经销商编码}-{6 位流水}；创建后不可修改 |
| 门店名称 | 文本 | 是 | ≤ 80 字符，按招牌名称录入；重复校验见业务规则 |
| 门店简称 / 别名 | 文本 | 否 | ≤ 40 字符，用于移动端快速检索与口语化识别 |
| 门店分类 | 下拉 | 是 | 取自门店分类，决定默认拜访频次与陈列要求 |
| 渠道 | 下拉 | 是 | 默认带出分类关联渠道，可覆盖 |
| 所属业务单元 | 下拉 | 是 | 即所属经销商，决定价格与库存来源 |
| 负责业务员 | 人员选择 | 是 | 必须是本经销商在职业务员；变更时记录交接时间 |
| 所属线路 | 下拉 | 条件 | 默认线路必填，用于生成拜访计划；支持标记主线路 |
| 门店等级 | 枚举 | 是 | A/B/C/D，默认继承分类 |
| 所在区域 | 级联 | 是 | 省（Province）/市（City/Municipality）/区（Barangay）/街道，按菲律宾行政区划三级 |
| 详细地址 | 文本 | 是 | ≤ 200 字符，门牌号、楼层、 landmark 描述 |
| 坐标 | 坐标 | 是 | 经纬度保留 6 位小数；移动端采集或地图选点，允许手工校正 |
| 联系人 | 文本 | 是 | ≤ 40 字符；店主或采购负责人 |
| 联系电话 | 文本 | 是 | 允许本地手机号与固话格式，支持多个号码以分号分隔 |
| 营业时间 | 文本 | 否 | 如 06:00—20:00，用于配送到达时间参考 |
| 门店类型 | 枚举 | 否 | 独立店/连锁店/市场摊位/流动摊点；连锁店需填写连锁名称 |
| 冰柜数量 | 整数 | 否 | 0—20，用于陈列资源投放统计 |
| 冰柜品牌归属 | 枚举 | 否 | 蒙牛投放/门店自有/竞品投放/无冰柜 |
| 主要竞品 | 多选 | 否 | 用于竞品陈列分析，选项由基础数据维护 |
| 信用额度 | 数值 | 是 | 0—999999，单位 PHP；0 表示现款现货 |
| 账期天数 | 整数 | 是 | 0—90 天，默认继承渠道 |
| 结算方式 | 多选 | 是 | 现金/支票/银行转账/GCash/Maya/赊销 |
| 开票信息 | 文本 | 否 | 纳税人识别号与开票抬头，赊销客户必填 |
| 首访日期 | 日期 | 否 | 首次成功拜访日期，用于计算新店存活率 |
| 客户状态 | 枚举 | 是 | 潜在/活跃/休眠/关闭；由系统按规则自动变更，可人工覆盖 |
| 门头照片 | 图片 | 条件 | 首次建档必填；≤ 5MB，带水印 |
| 内景 / 冰柜照片 | 图片 | 否 | 最多 5 张，用于陈列核查 |
| 备注 | 文本 | 否 | ≤ 500 字符 |

**表42  客户业务规则**

| 编号 | 业务规则 |
| --- | --- |
| BR-CUS-01 | 重复校验：新增时若同一经销商下存在名称相似度大于 80% 且坐标距离小于 50 米的门店，系统提示疑似重复并要求确认或合并 |
| BR-CUS-02 | 移动端新增门店必须包含门头照与坐标，否则不允许提交；提交后进入待审核，审核前不可下单 |
| BR-CUS-03 | 信用额度变更超过原额度 50% 或超过 5 万比索时，须经销商管理员或财务审批 |
| BR-CUS-04 | 负责业务员变更时，客户的历史订单与应收不随之转移，仅影响后续拜访与订单归属 |
| BR-CUS-05 | 客户连续 60 天无有效订单自动标记“休眠”，连续 180 天标记“关闭候选”，关闭需管理员确认 |
| BR-CUS-06 | 已关闭客户重新激活需重新采集门头照与坐标，且须经管理员审核 |
| BR-CUS-07 | 坐标缺失或精度低于 50 米的门店，不参与签到距离校验，改为“异常签到”流程并记录原因 |

## 2026-11-11 销售与资金台账联动

客户订单、回款、欠款从新增销售台账实时投影，签收形成应收，退货冲减应收、退款冲减净回款；收款详情保留原收款额和退款信息，客户汇总按净回款。修改客户不覆盖销售业务数据。新销售订单可进入完整履约/发票详情，旧历史往来保留。销售应收菜单只汇总本次销售台账，客户档案另含历史往来，范围不同不能混同。具体行为和验证见[销售一期实现与验收](../06-销售管理/一期实现与验收.md)。
