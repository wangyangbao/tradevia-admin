## 金额与统计口径

- 金额以整数“分”存储，展示币种为菲律宾比索 PHP，保留两位小数。
- 累计成交包含已签收、配送中订单，不含待审核、已取消订单。
- 待收货款为已签收订单减去关联的已确认收款；待确认、已作废收款不抵减应收。
- 账款到期日早于当前业务日期且仍有余额时计入逾期。
- 分类月均销额按近三个完整自然月成交金额除以三，包含下级分类，仅统计有权查看的客户。
- 客户汇总不直接复用旧的首页大盘与收款对账示例数字，避免将不同演示口径相加。

## 客户字段取舍与定位

- 优先呈现客户名称 / 编码、分类 / 状态、经销商 / 业务员、主要联系人 / 职务 / 电话、完整联系地址、门店坐标、营业时间、备注，以及订单 / 回款所需的信用与结算信息。
- 联系地址复用客户地址页签中唯一的默认地址，不新增另一套顶层地址字段。修改默认地址后，档案顶部、详细信息和定位链接同步更新；只读账号可查看定位，不能修改地址。
- 定位使用档案中的经纬度生成 Google 地图链接，保留六位小数，点击后在新窗口查看；未填写或坐标超出有效范围时，不生成定位链接。产品已明确定位采集由移动端业务员现场完成，PC 端本轮不继续处理经纬度录入体验，也不增加设备定位、地址自动解析或地图选点。现有演示表单的经纬度输入及校验暂时保留。
- 不照搬参考图中的传真、网址、锁定 / 退回原因、外部负责人、ERP 编码、协议、认证、法人、营业执照与二维码等字段；现有业务字段和历史数据继续保留。

## 数据与权限

客户档案与台账存储键为 `tradevia-customers-v1-{租户ID}`，分类继续使用 `tradevia-basic-data-v1-{租户ID}`。常用筛选按租户、所属组织、账号分别保存。所有写入重新读取组织权限；越级、跨租户及普通成员写入会被拒绝。多页面修改通过数据版本检查提示重新核对；数据损坏不会静默恢复样例覆盖原文，存储空间不足时明确提示未保存。

分类被真实客户引用时不能删除，即使旧基础档案中的示例引用数为零也会检查。停用分类不删除历史客户，客户的现有交易关联使用稳定 ID，不依赖门店名称。

## 尚未接入的业务

- 服务端 API、数据库和正式的多租户权限校验；本浏览器修改不会自动同步到其他设备。
- 财务审批、移动端待审核建档、关闭客户重新激活审核、批量导入、重复客户合并。
- 新增内景 / 冰柜多图附件、菲律宾行政区划字典级联；移动端业务员现场定位采集及其数据同步尚未接入本 PC 演示，本轮不开发。
- 60 / 180 天规则当前提供休眠 / 关闭候选提醒，不在前端静默改写客户状态。关闭候选仍需管理员确认。
- 客户主线路字段记录关联；尚不自动改写旧拜访路线模块的分配和任务。原路线模块仍使用预置门店快照。
- 新收款、订单审核、发货、出库、应收结转、实际支付及外勤签到。现有收款对账模块仍为独立示例。

## 验收步骤

1. 进入客户列表，依次搜索编码、名称、电话，选择分类、状态、大区、经销商与更多条件；检查结果、页码及导出。
2. 切换每页五条，翻到第二页再搜索；应回到第一页。保存查询并刷新，再点击常用筛选恢复。
3. 打开 Aling Nena Store，检查顶部完整联系地址，详细信息中的联系信息、地区定位、经纬度与收货人电话；点击查看定位，应在新窗口按当前门店坐标打开地图。检查欠款、逾期、账期与信用使用率；切换七个页签仍能查看顶部地址，返回后保留列表查询。
4. 从详细信息直接修改默认地址与坐标，保存后检查顶部、详细信息和定位链接同步更新，刷新仍保留；增加地址 / 联系人，设为默认 / 主要，再尝试删除旧记录；默认和主要记录不能直接删除。
5. 发布跟进并补录已发生拜访，刷新后检查记录、页签数量和右侧时间线。未来时间不允许作为已发生拜访保存。
6. 新建客户，核对必填项、经纬度、照片；选择分类应带入默认值，赊销要求信用额度和开票信息。
7. 编辑分类、业务员、信用额度或账期，必须勾选确认；大幅额度调整因审批未接入而阻止直接保存。
8. 关闭客户必须填写原因；重新激活应显示重新采集与审核要求，不能通过编辑状态绕过。
9. 从销售模块为未关闭客户新建演示订单，返回客户档案订单页签检查新订单；刷新后销售列表和客户档案均保留该单据。
10. 使用经销商账号和普通成员账号检查组织范围及只读权限；直接访问其他经销商客户 URL 不能显示其资料。
11. 切换租户，不应出现上一个租户的客户、金额与常用筛选。检查深色主题及窄屏的表格横向滚动和页签滚动。
