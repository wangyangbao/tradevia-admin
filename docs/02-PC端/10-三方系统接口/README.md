## 3.10.2  订单接口

订单接口是本期唯一必须落地的三方接口，用于承接总部或电商平台下发的订单。接口设计遵循四项原则：统一鉴权、强制幂等、失败可重试、全程可追溯。任何一项缺失都会在高峰期造成重复订单或数据丢失。

**表88  订单接口技术约定**

| 要素 | 要求 |
| --- | --- |
| 协议与格式 | HTTPS + JSON；字符集 UTF-8；时间格式 ISO 8601 带时区（+08:00） |
| 鉴权 | OAuth2 客户端凭证模式或签名鉴权（AppKey + 时间戳 + 签名），令牌有效期 2 小时，失败自动刷新 |
| 幂等 | 请求头必须携带 externalOrderNo 作为幂等键，重复请求返回首次处理结果与同一内部订单号 |
| 限流 | 单客户端默认 20 次/秒，超限返回 429 并提示重试间隔 |
| 重试 | 调用方失败后按 1s/5s/30s/5min 退避重试，最多 6 次；本系统侧提供手动重推入口 |
| 验签与校验 | 校验必填字段、金额勾稽、商品存在性、客户归属；任一失败返回明确错误码且不落库 |
| 日志 | 记录请求报文、响应报文、耗时、结果与追踪号，保留 180 天，支持按追踪号检索 |
| 监控 | 失败率超过 5% 或连续 10 次失败时告警至接口负责人 |

**表89  订单接口字段映射**

| 外部字段 | 内部字段 | 必填 | 转换规则 |
| --- | --- | --- | --- |
| externalOrderNo | 外部订单号 | 是 | 作为幂等键，写入订单表并建立唯一索引 |
| distributorCode | 所属经销商 | 是 | 映射为业务单元编码，未匹配则整单拒绝 |
| outletCode / outletName | 客户 | 是 | 优先按编码匹配，编码为空时按名称 + 地址模糊匹配并人工确认 |
| orderDate | 订单日期 | 是 | 转为本地时区日期，允许 T-1 至 T+7 的日期 |
| deliveryDate | 配送日期 | 否 | 为空时按访销规则取订单日期次日 |
| items\[\].skuCode | 商品 | 是 | 映射为内部 SKU，未匹配则整单拒绝并返回明细行号 |
| items\[\].qty / unit | 数量 / 单位 | 是 | 单位须在商品换算表中存在，按换算率折算为基本单位 |
| items\[\].price | 单价 | 否 | 为空时按内部价目表取价；不为空时校验是否低于最低售价 |
| totalAmount / taxAmount | 应收金额 / 税额 | 是 | 校验与明细合计一致，差异超过 0.01 时拒绝 |
| remark | 订单备注 | 否 | 截断至 200 字符并保留原文至扩展字段 |
| callbackUrl | 状态回传地址 | 否 | 为空时使用系统默认配置 |

状态回传采用事件推送模式：订单每次状态变更（审核通过、发货、签收、取消）都向调用方推送一次事件，事件包含内部订单号、外部订单号、状态码、发生时间与失败原因。推送失败按重试策略补推，并提供“按时间段重推”的运维工具，避免调用方因自身故障漏单。

<a id="section-3-10-3"></a>

## 3.10.3  接口异常处理与对账

接口异常分为三类：请求不合法（字段缺失、格式错误）直接拒绝并返回错误码，不落库；业务校验失败（商品不存在、客户归属不符）整单拒绝并记录原因；系统异常（超时、数据库故障）返回可重试标识，由调用方重试。三类错误使用不同的错误码段，禁止用同一个“系统错误”笼统返回。

每日凌晨执行接口对账：比对调用方订单清单与本系统成功落库的订单，输出差异清单（漏单、重复单、金额不一致），差异由接口负责人当日处理完毕。对账结果留档，作为月度接口健康度考核依据。
