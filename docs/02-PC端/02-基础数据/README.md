# 3.2  基础数据

> 来源：《蒙牛菲律宾冰淇淋经销商运营系统 PRD V1.0》第 3.2 节。原文状态为“需求评审稿（待业务方确认）”，本文件按模块整理，未改变业务规则。

[返回文档总目录](../../README.md)

基础数据包含单位、币种、品牌、渠道四类。它们的共同特征是变更频率低但被大量业务引用，因此设计要求一致：新增需填编码与名称，修改受限字段，停用前校验引用，删除仅限零引用。四类数据均由总部管理员维护，经销商只读。

<a id="section-3-2-1"></a>

## 3.2.1  单位

单位用于表达商品的计量方式。冰淇淋业务中同时存在“箱”“支”“袋”“盒”等单位，库存以箱为主单位、销售可按支计价，因此单位表必须支持换算关系，而不仅是名称维护。系统采用“基本单位 + 换算率”模型：每个商品指定一个基本单位，其他单位以换算率表达与基本单位的关系。

**表30  单位字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 单位编码 | 文本 | 是 | 全局唯一，≤ 10 字符，建议使用英文缩写（CTN、PCS、BAG） |
| 单位名称 | 文本 | 是 | 中文与英文各一，≤ 20 字符 |
| 单位类型 | 枚举 | 是 | 数量单位/重量单位/体积单位 |
| 是否基本单位 | 布尔 | 是 | 同一商品只能有一个基本单位；基本单位换算率为 1 |
| 换算率 | 数值 | 条件 | 非基本单位必填，正整数，表示 1 个该单位等于多少个基本单位 |
| 小数精度 | 整数 | 是 | 0—3，控制该单位下数量的显示精度 |
| 状态 | 枚举 | 是 | 启用/停用 |

**表31  单位业务规则**

| 编号 | 业务规则 |
| --- | --- |
| BR-UNIT-01 | 已被商品引用的单位不可删除，仅可停用；停用后该单位不可用于新建商品 |
| BR-UNIT-02 | 修改换算率将影响历史单据的显示，系统仅允许在无业务数据时修改，否则须新建单位 |
| BR-UNIT-03 | 商品的基本单位必须为“启用”状态，且换算率必须为整数，避免出现 0.333 箱的情况 |
| BR-UNIT-04 | 销售单位与库存单位不同时，订单保存前按换算率折算库存扣减量，折算结果四舍五入到基本单位精度 |

<a id="section-3-2-2"></a>

## 3.2.2  币种

本位币为菲律宾比索（PHP），美元与人民币作为辅助币种，主要用于总部报表折算与进口成本核算。币种表维护符号、小数位与汇率，汇率按生效日期分段保存，历史单据始终使用业务发生日的汇率，不随汇率更新而重算。

**表32  币种字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 币种编码 | 文本 | 是 | ISO 代码，如 PHP、USD、CNY，全局唯一 |
| 币种名称 | 文本 | 是 | 如“菲律宾比索” |
| 货币符号 | 文本 | 是 | 如“₱”，用于金额展示 |
| 小数位数 | 整数 | 是 | PHP 为 2；展示与四舍五入均按此设置 |
| 是否本位币 | 布尔 | 是 | 全局仅一个本位币，切换需事业部审批 |
| 当前汇率 | 数值 | 条件 | 非本位币必填，保留 6 位小数，表示 1 单位该币种折合本位币的金额 |
| 汇率生效日 | 日期 | 条件 | 非本位币必填；同一币种同一日期不允许重复 |
| 状态 | 枚举 | 是 | 启用/停用 |

**表33  币种业务规则**

| 编号 | 业务规则 |
| --- | --- |
| BR-CUR-01 | 订单、收款等业务单据默认使用业务单元的本位币，不可由业务员切换 |
| BR-CUR-02 | 汇率变更仅影响变更生效日之后的单据，已保存单据的汇率字段只读 |
| BR-CUR-03 | 报表折算差额不计入业务金额，单独在报表附注中列示折算汇率与差额 |
| BR-CUR-04 | 本位币不可停用，非本位币停用后不影响已引用它的历史单据 |

<a id="section-3-2-3"></a>

## 3.2.3  品牌

品牌用于区分蒙牛主品牌与子品牌，支撑按品牌维度的销量与铺货分析。品牌与事业部绑定，一个品牌只能归属一个事业部；商品必须选择品牌，报表可按品牌逐级下钻到品类与 SKU。

**表34  品牌字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 品牌编码 | 文本 | 是 | 全局唯一，≤ 12 字符 |
| 品牌名称 | 文本 | 是 | 中文与英文各一 |
| 所属事业部 | 下拉 | 是 | 从业务单元中类型为事业部的记录选择 |
| 品牌标识 | 图片 | 否 | 用于单据与报表页眉，≤ 1MB，PNG 透明底 |
| 排序号 | 整数 | 否 | 影响报表与筛选列表的展示顺序 |
| 状态 | 枚举 | 是 | 启用/停用；停用后该品牌下商品不可新增订单 |

**表35  品牌业务规则**

| 编号 | 业务规则 |
| --- | --- |
| BR-BRAND-01 | 品牌停用前须校验其下商品是否仍有在售记录，存在则在售商品需先下架 |
| BR-BRAND-02 | 品牌编码一经使用不可修改，新增子品牌须单独建档，不得复用编码 |

<a id="section-3-2-4"></a>

## 3.2.4  渠道

渠道是价格政策与拜访策略的分类依据。菲律宾市场至少需要区分传统渠道（Sari-sari 社区店）、现代渠道（超市与便利店）、餐饮渠道（餐厅、甜品店、咖啡店）、特通渠道（加油站、学校、景区、影院）。渠道决定默认价目表、默认账期与默认拜访频次，减少逐个客户配置的工作量。

**表36  渠道字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 渠道编码 | 文本 | 是 | 全局唯一，≤ 12 字符 |
| 渠道名称 | 文本 | 是 | 中文与英文各一 |
| 渠道类型 | 枚举 | 是 | 传统/现代/餐饮/特通/其他；影响默认参数与报表分组 |
| 默认价目表 | 下拉 | 否 | 选择价目表模块中的记录，作为该渠道客户的默认取价依据 |
| 默认账期 | 整数 | 否 | 0—90 天，新建客户时带入，可在客户档案中覆盖 |
| 默认拜访频次 | 枚举 | 否 | 每周 2 次/每周 1 次/每两周 1 次/每月 1 次 |
| 是否需要冷链 | 布尔 | 否 | 勾选后该渠道客户默认要求冰柜陈列，拜访动作增加陈列检查 |
| 状态 | 枚举 | 是 | 启用/停用 |

**表37  渠道业务规则**

| 编号 | 业务规则 |
| --- | --- |
| BR-CHN-01 | 渠道停用后，新客户不可选择该渠道，存量客户保留并在列表标记“渠道已停用” |
| BR-CHN-02 | 修改渠道默认价目表仅影响新建客户，存量客户的价格政策不自动变更，需另行批量调整 |
| BR-CHN-03 | 同一客户只能属于一个渠道；跨渠道经营的门店（如既做零售又做餐饮）以主要销售形态归类 |
