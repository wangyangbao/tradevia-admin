## 3.9.1  角色

角色是权限的集合，人员通过角色获得能力。系统预置 9 个角色（见 2.5 节），并允许总部管理员创建自定义角色。角色必须绑定适用的业务单元层级，例如“大区经理”角色只能分配给大区及以下人员，“总部管理员”只能分配给总部人员，避免出现经销商人员拥有全局权限的越权情况。

**表84  角色字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 角色编码 / 名称 | 文本 | 是 | 全局唯一，名称 ≤ 30 字符 |
| 适用层级 | 多选 | 是 | 总部/事业部/大区/经销商，决定该角色可分配给哪些人员 |
| 角色类型 | 枚举 | 是 | 管理类/业务类/财务类/只读类 |
| 数据范围 | 枚举 | 是 | 本人/本部门/本业务单元/本单元及下级/指定范围 |
| 功能权限 | 树选择 | 是 | 菜单与按钮级权限，见 3.9.2 |
| 字段权限 | 配置 | 否 | 对敏感字段设置可见、可编辑、脱敏三档 |
| 状态 | 枚举 | 是 | 启用/停用 |
| 备注 | 文本 | 否 | 说明角色用途，便于后续维护 |

<a id="section-3-9-2"></a>

## 3.9.2  权限分配

权限分配页面左侧为角色列表，右侧为权限树。权限树分为四层：模块（一级菜单）、菜单（二级菜单）、操作（按钮级，如新增、审核、导出）、数据（可见范围）。勾选模块自动勾选其下全部菜单与操作，取消任一子项则模块显示为半选状态，避免出现“模块已开但菜单不可见”的矛盾配置。

**表85  权限类型**

| 权限类型 | 粒度 | 示例 | 说明 |
| --- | --- | --- | --- |
| 菜单权限 | 二级菜单 | 可见“销售订单”菜单 | 控制页面入口，不控制按钮 |
| 操作权限 | 按钮 | 新增订单、审核订单、导出报表 | 控制具体动作，未授权按钮置灰或隐藏（按配置） |
| 数据权限 | 组织范围 | 仅可见本经销商数据 | 与角色数据范围叠加，取交集 |
| 字段权限 | 字段 | 成本价脱敏、客户手机号脱敏 | 支持按角色配置，脱敏后显示为掩码 |
| 审批权限 | 流程节点 | 审核 5 万比索以上订单 | 与金额阈值绑定，超出阈值自动流转至上级 |

**表86  权限业务规则**

| 编号 | 业务规则 |
| --- | --- |
| BR-PRM-01 | 权限变更即时生效，已登录用户在下一次请求时按新权限校验，不要求重新登录 |
| BR-PRM-02 | 涉及审核、作废、导出、改价四类敏感操作的权限变更，须记录操作人与变更前后的权限项 |
| BR-PRM-03 | 角色停用后，已分配该角色的人员失去对应权限，系统在人员列表标记“角色失效” |
| BR-PRM-04 | 同一人员拥有多个角色时，权限取并集，数据范围取最大范围，但不得突破其所属业务单元的上级范围 |
| BR-PRM-05 | 经销商管理员不得授予本单元人员“总部管理员”或跨经销商数据权限 |

<a id="section-3-9-3"></a>

## 3.9.3  数据权限模型

数据权限采用“组织路径 + 范围类型”的组合模型。每个业务单元在库中保存完整路径（如 /HQ/ICE/MM/N01），查询时按当前用户所属单元路径进行前缀匹配，从而实现“本单元及下级”的收敛。这种模型的好处是新增经销商不需要重新配置权限，只要挂到正确的上级即可自动继承。

经销商之间的数据默认完全隔离，包括门店、订单、库存、收款与人员。大区经理可见本大区全部经销商的数据但不能修改；事业部与总部可见汇总数据与明细，但导出时按角色限制导出范围，防止数据外泄。
