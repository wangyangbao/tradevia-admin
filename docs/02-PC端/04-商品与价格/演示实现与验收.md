# 商品管理：实现与验收

更新时间：2026-11-10。依据第 3.4 节 PRD 和用户提供的五张参考图实现，沿用现有紧凑工作台布局与主题。原始 PRD 保持原文，本文件说明当前演示的实际范围。

## 入口与主要能力

左侧「商品管理」提供三个菜单：

| 菜单 | 直接入口 | 已实现 |
| --- | --- | --- |
| 商品分类 | `http://127.0.0.1:5173/#productCategories` | 两级分类树、展开收起、搜索筛选、新建同级/下级、编辑、启停、零引用删除、品牌、默认税率、必铺品项、排序、按剩余天数配置临期预警、导出 |
| 商品 | `http://127.0.0.1:5173/#products` | 独立 SKU 建档、品牌及分类关联、箱规/单位换算、销售和库存税务属性、图片、EAN-13 一品多码、详情、关联价目表、上下架、删除、CSV 导入与错误明细、导出 |
| 价目表 | `http://127.0.0.1:5173/#priceLists` | 列表筛选、分步建档、适用客户、商品多选、批量改价/折扣、阶梯价格、赠品、明细有效期、草稿、发布/审核/退回/停用、详情、操作记录、客户取价试算 |

商品分类复用原基础档案数据，不另建一份分类；原分类地址继续有效。旧基础数据说明中的“最多三级”以本轮 PRD 校准后的“最多两级：品类—系列”为准。上下级归属同一品牌；存在商品引用后不能变更分类品牌。

## 核心规则

- 总部及所属事业部管理员维护商品与价目表；大区、经销商和普通成员查看与自身组织相关的数据。更换租户不复制商品或价格；每次写入重新获取当前组织权限。经销商执行价授权区间及越权调价审批尚未接入，因此当前没有经销商调价入口。
- 商品编码唯一且保存后锁定；删除后编码不可复用。条码验证 EAN-13 校验位，同品内与跨商品禁止重复。同口味不同规格各建独立 SKU。
- 商品基本单位通常为箱，销售单位可以是箱或支；不同单位时以箱规计算 `1 销售单位 = 1/箱规 基本单位`，不修改单位档案的通用默认换算率。冰淇淋固定冷冻与启用批次。商品被订单或价目表使用后，品牌、含税口径及单位换算锁定。
- 商品分类默认税率在选择分类时带入，后续修改分类不回写存量商品；必铺标记与预警天数从当前分类展示。商品图片支持 PNG、JPEG、WebP，不超过 2 MB。
- 价目表类型为标准价、渠道价、促销价、客户专属价、经销商结算价。按两步维护：①基本信息及适用客户；②选择商品、维护价格。调整业务单元、币种或含税口径后清空相关明细，要求重新选择。
- 适用客户可选全部、按条件、指定客户。按条件时渠道、分类、等级之间同时满足，同一条件多选任一满足；选上级客户分类包含其下级。渠道价须选渠道；客户专属价须指定客户或客户分类；关闭和业务单元以外的客户不可指定。
- 单价使用四位小数的定点整数存储，折扣率表示实付比例：折后价 = 单价 × 折扣率 / 100，100% 表示原价。商品成本、最低售价与标准零售价口径为 PHP；辅助币种按生效汇率核对最低售价，取价试算按所选币种分别匹配，不跨币种混价。
- 明细日期为空时继承价目表整体期间。相同商品、相同起订量的重叠明细禁止保存；不同起订量视为阶梯档位，同表内按满足条件的最大起订量取价。这是对 PRD“多档阶梯”与“商品明细不得重叠”的组合实现口径。
- 同业务单元、同币种、同类型、同优先级且适用范围与期间重叠的已发布或待审核价目表禁止重复发布。草稿可以没有商品明细，发布至少需要一条有效明细。
- 促销价、客户专属价、折后低于最低售价的价目表进入待审核，审核前不取价。通过后记录审核人、时间并按日期生效。编辑后重新发布或审核；不沿用旧审批。生效表到期自动作为失效处理，7 天内到期在列表提示。
- 取价按客户专属价 > 促销价 > 渠道价 > 标准价；同类型先比较数字优先级，再比较整体生效开始日期，仍冲突取较低价格。经销商结算价不参与终端客户销售取价。
- 现有「新建订单」已关联在售商品及 PHP 价目表，选择客户、商品、销售单位和数量后取价。没有匹配价格时阻止保存，停售商品不可下单。保存商品名称、单位、单价、税率、赠品与价目表来源快照；后续改价、改名或停用不回写历史订单。低价订单保持待审核，赠品按零金额明细关联主商品。
- CSV 批量导入先校验所有行，再整批新增；存在错误不部分写入。支持下载空模板、UTF-8 CSV、多条码分号分隔、错误行与原因展示及导出。编码已存在时拒绝导入，避免误覆盖。

## 建议体验顺序

1. 使用总部账号 `hq@tradevia.demo`（初始密码 `Demo123456`），或点击“体验演示工作台”，进入商品分类。
2. 展开「冰淇淋」，在一级分类新建下级；二级分类没有再建下级入口。尝试把父分类移至子分类、跨品牌选择上级，保存应阻止。
3. 新建商品，选择品牌、分类，检查税率带入；填写独立 SKU、规格、销售单位和箱规，切换“库存与税务”核对保质期、冷冻、批次和含税标记。刷新后档案保留。
4. 为商品维护有效条码、图片，重复使用条码或修改已有编码应阻止；下架后不出现在新增价目表商品选择和新订单中。
5. 在商品页下载 CSV 模板，填两行相同编码上传：检查错误行，确认没有部分新增。修正后重新上传并确认导入。
6. 新建渠道价，选择业务单元、有效期、渠道，再下一步。添加在售商品，修改单价和折扣，批量修改所选行，添加不同起订量阶梯；试填含税口径不一致、重复档位或越界明细日期。
7. 创建促销价或客户专属价，选客户并维护价格，提交后显示待审核。审核通过后，在“客户价格试算”选择匹配客户和日期；过期日期应回退至标准价。核对开始日、结束日当天仍在有效期内。
8. 从销售订单创建演示订单，检查取价来源；之后调整价目表，再打开历史订单与客户档案中的关联订单，确认原单价和金额保留。四位小数单价的小计按金额两位小数显示，赠品金额为 0。
9. 切换事业部、大区、经销商及普通成员，检查维护按钮与组织范围；总部切换“海岛食品”，不应出现哈尼 SKU 和价目表。
10. 两个页面同时编辑同一模块，先保存一个，再保存旧窗口，应提示重新打开核对；存储损坏或空间不足时保留原数据，不假报成功。

## 验证与边界

已通过 `npm run lint`、`npm run build`、`npm test`（132 项）。新增检查覆盖分类、条码、引用、组织权限、币种、价格有效期、范围冲突、折扣、审批状态、阶梯价、到期回退、订单快照、赠品、CSV 整批校验和页面结构。

当前 Work 设置禁止自动操作本地浏览器，未完成真实浏览器点击、深浅主题、窄屏和截图验收；这些项目需在预览页按上述步骤复核。代码已提供横向滚动、弹窗滚动及窄屏布局，不能把实现了样式等同于已通过视觉验收。

当前仍为浏览器演示，商品与价格存储键为 `tradevia-catalog-v1-{tenantId}`，分类沿用 `tradevia-basic-data-v1-{tenantId}`，订单快照保存在客户业务台账。不同设备不共享。审核为本地状态演示，未接入真实审批流、低价阈值升级、数据库事务、服务端权限或审计、库存扣减、真实订单履约、退货执行与财务处理。即将到期仅在页面提示，没有后台推送任务；预警配置支持剩余天数，尚未联动库存批次告警与预警比例；销量/铺货率报表入口暂未提供。现有创建订单入口仍沿用原工作台对哈尼总部的开放范围，外币订单尚未开放。
