## 正常业务流程

### 访销

1. 选择访销订单，进入完整开单页；选择客户后带出经销商、业务员、主线路、结算方式和收货信息。
2. 添加在售商品，按客户、日期、单位与数量自动取价。可按箱或支销售，箱价没有直接配置时从支价乘箱规派生。修改成交价必须填写原因；低于最低售价标注待人工审核，零价只允许系统赠品。
3. 保存草稿或提交待审核。无价格、客户/组织失效、数量错误、库存缺口、赊销额度不足会阻断。审核人重新核对商品、库存、信用后通过，开始占用库存；驳回意见至少 10 字。
4. 从已审核订单生成一笔或多笔发货单。累计草稿和有效发货数量不得超过订单数量；部分发货填写原因，差额保留待发，不自动关闭订单。
5. 发货单提交时生成唯一出库单、分配未过期且非禁售批次、扣减实存，同时释放相应订单占用；未出库部分继续占用。不允许提前提交未来日期的发货单。
6. 登记客户实际签收，签收数量形成应收；可继续登记一次或多次回款，自动核销本单应收。
7. 配送处理完成后，可按净销售金额生成发票。开票与收款分别跟踪；开票不增加应收，也不再次扣库存。

### 车销

车销使用所属经销商车仓，当日下单、当日交付。选择现款方式时，必须确认现场实收及实际收款；非现金填写凭证，部分回款填写说明，超收禁止提交。选择赊销时校验客户是否开通账期与信用额度。

正常价格提交后自动审核、生成发货单、出库、签收和现场收款，作为同一份销售台账一次保存，避免生成一半单据。低价车销进入待审核，管理员通过后才执行交付；不能绕过价格审批，也不能在次日直接批准历史车销，应驳回后重新核对日期和实收。

## 数量与库存口径

- 明细数量为整数，支持箱/支切换；单笔商品数量 1～10000；价格保留四位小数，金额按分保存，逐行计算税额。
- 金额、税率、含税方式、价目表来源、销售单位、箱规和赠品在订单保存时锁定。发货、出库、发票不另行改价。
- 可售实存 = 未过期且非禁售批次的期初 + 可再销售退回入库 − 销售出库。
- 订单占用 = 已审核订单尚未出库的商品数量，赠品一并计算。仓库商品可用 = 可售实存 − 其他有效订单占用。库存页面的占用/可用按仓库商品汇总，并非每个批次各自占用，不可重复相加。
- 订单累计发货不大于订购量；出库记录逐笔关联发货和批次；库存扣减只发生在出库，不能靠改订单状态扣库。
- 已出库单据不能作废；审核订单作废要求管理员且不得已有出库，确认后取消未出库发货草稿并释放占用。
- 批次分配采用先到期先出，库存不足时整个操作不保存，不留部分扣减。

## 配送差异与退货

部分签收或整单拒收需填写原因并上传 PNG/JPG/WebP 现场照片，单张最大 2MB；登记人还须确认拒收商品已实际回仓并完成检验或报损。实际接受数量形成应收，拒收数量生成金额为零的“拒收退回”记录，避免再次冲减不存在的应收。可再销售商品回补原有效批次，报损不回补可售库存。尚未回仓时保持配送中，不提前登记回库。

已签收商品后续退货由管理员从订单登记，须选择来源发货单、数量、原因及实物处理。累计退货不能超过该发货单实际接受数量；不能将原已拒收数量再退一遍。原批次已过期或禁售时不能回补可售库存，需选择报损。

退货只冲减一次应收。已有开票登记时须先完成原票作废登记，再退货与重新开票；未确认的旧发票草稿自动作废。已作废发票仍保留当时的数量和金额快照。报损记录尚未接入独立质检或库存报损审批单。

## 资金与发票口径

| 指标 | 口径 |
| --- | --- |
| 签收金额 | 按商品累计实际签收数量和订单快照计算，不含拒收商品 |
| 净应收 | 签收金额 − 后续已签收商品退货冲减 |
| 净回款 | 已确认收款 − 已登记退款，作废收款不计入 |
| 待收余额 | 净应收减净回款，最低为零 |
| 待退款 | 净回款超过净应收的部分；管理员登记实际退款凭证后减少 |
| 发票金额 | 配送处理完成后的净销售金额；同一订单同时只允许一张有效发票 |

收款状态由金额和到期日计算，不能人工勾选。首批签收确定账期，后续分次签收不顺延首批到期日。赊销信用检查包含客户历史欠款、其他已审核订单未结清应收和未履约金额，防止拆多单绕过额度。

收款不可超过本单待收；非现金凭证号按方式检查重复，发票凭证和退款凭证检查重复。退款须先完成实际支付，再在系统登记凭证；系统不执行真实转账。管理员可作废错误收款，余额重新计算；已退款后不允许作废造成净回款为负的收款。

四位小数单价在拆分配送、连续退货时，按累计数量差额计算，避免逐次舍入产生总额不一致。

## 客户、商品与历史数据衔接

客户档案直接读取销售台账投影：订单净销售、回款、欠款随签收、退货与退款变化。新增投影订单提供完整履约详情入口；收款保留原收款与退款信息，客户汇总使用净回款，销售详情保留逐笔原收款及退款记录。维护客户资料不会覆盖销售台账，也不会将投影当作另一份业务源重复写入。

原有历史订单与回款保留在订单“历史台账”和客户档案，可查看原记录；历史台账不补造缺失的发货、库存批次或库存流水。销售应收台账仅统计本次销售业务产生的记录，客户档案还包含既有历史往来，两者范围不能直接混同比较。

新订单使用既有商品、价目表、客户和组织档案，不为填充演示订单擅自补商品价格。当前标准价属于冰淇淋事业部，缺少适用价目表的经销商客户仍会正确拦截下单。商品与价目表后续变化不改写历史订单快照。

经营概览订单入口及全局搜索可进入新销售详情；概览中的既有趋势、渠道图和目标仍属于早期演示口径，本次未将其升级为整套财务报表。

## 建议人工验收步骤

1. 使用总部演示账号打开 `#orders`，确认四个销售子菜单。点击新建，分别进入访销/车销全页表单。
2. 访销选择 Aling Nena Store，添加商品，配送日期选当天，提交审核；检查订单待审核和商品价格来源。通过审核后查看库存占用。
3. 从订单生成发货，填写车辆，先发一部分；提交后检查关联出库和库存流水，剩余数量继续待发。
4. 登记正常签收或部分签收；差异上传照片并确认实际回仓。核对签收金额、拒收退回及仓库数量。
5. 分次登记现金/钱包回款，测试重复凭证、超收、部分说明校验。待收金额应随回款减少。
6. 配送处理结束后生成发票，填入凭证确认登记；净应收不得再次增加。
7. 对已回款订单先作废开票登记，再退部分商品。检查应收冲减、待退款；实际退款后登记凭证，检查净回款一致。
8. 打开客户档案、销售库存和应收台账，核对同一笔订单；刷新后确认记录保持。
9. 使用经销商或普通成员账号复核组织范围和管理员按钮；编辑时切换菜单，确认未保存内容保护。

## 已知限制与待接入

当前是可操作并持久保存的本地前端业务闭环，尚无服务端数据库、真实仓库接口、真实支付/银行/钱包扣款、税务开票和外部审批。账号及权限沿用既有组织演示机制，不构成生产安全边界。

单次业务变化写入一份销售台账，保存失败不会留下半套单据；版本号阻止已加载的旧页面覆盖新记录。但本地版本校验不能替代服务端事务、跨设备并发锁或长期审计存储。

本次不包含多订单合并发货、跨订单收款分摊、法定红字发票、热敏打印模板、移动端扫码签名/GPS/离线同步、自动支付回执、车仓装卸调拨、采购入库、独立盘点/质检/报损审批和服务端定时逾期计算。订单日期目前限制为今天或前 7 天，不提供超期补录审批。金额币种限定 PHP，订单数量采用整数，未实现两位小数数量。

新增经销商后，仓库与期初库存仍需后续仓储能力接入，不自动虚构可售库存。现场照片保存于本地台账，容量受浏览器限制；失败会保留表单并提示重试，不属于正式影像归档。关闭编辑器有未保存提示，浏览器关闭由浏览器原生提示处理；打印、导出仍需真实浏览器复核。
