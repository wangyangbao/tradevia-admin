## 当前数据范围规则

1. 先确认登录账号在当前租户存在有效成员身份，再取得该成员所属的业务单元。
2. 四级严格为“总部 → 事业部 → 大区 → 经销商”，不能跳级；经销商不可新增下级业务单元，可创建内部部门。
3. 组织根为当前成员所属组织。上级、同级兄弟组织、其他租户均不进入业务单元树、人员目录、选择项或导出。根节点的上级展示“当前管理组织”，不暴露真实上级名称。
4. 管理员可管理本组织及下级；成员在组织架构中仅查看。角色只决定能否管理，不扩大所属组织的范围。
5. 只允许切换本人已加入的租户。总部演示账号加入了两个租户，下级演示账号仅加入哈尼冰淇淋租户。
6. 切换租户或重新登录后，重建页面筛选、部门选择及编辑窗口。展开状态按账号、租户、所属组织在当前标签页会话中分别保存。
7. 自助注册不自动获取总部身份或任何租户权限。演示租户成员由种子数据提供，新增人员由有权限的管理员创建。
8. 浏览器内保存组织数据与审计记录；多标签页通过存储变更及重新聚焦刷新。正式环境仍须服务端在每次请求中执行上述规则，浏览器演示不构成安全隔离边界。

## 本次已实现

### 业务单元

- 树形表格，首次默认显示当前组织与下一层级；支持逐行展开、全部展开/收起，并记忆当前会话的展开状态。
- 按名称、编码、类型及状态筛选，筛选结果保留当前范围内的祖先以展示关系。
- 新增下级、编辑、启用/停用、删除、可见在职人数统计及 CSV 导出。
- 当前租户已有一个总部，不提供重复创建总部的入口；经销商的新增下级入口禁用。
- 创建后编码、类型、上级不可修改，层级由父级决定；校验编码唯一、同级名称不重复。
- 联系信息、地址、默认币种/语言、经销商纳税识别号与账期、生效日期、排序、备注可维护。
- 停用必须填写原因，存在本级或下级在职人员、演示业务引用时阻止；启用要求上级启用。
- 删除二次确认并填写原因；有下级、部门、人员、演示业务引用或为当前组织根时禁止删除。
- 已停用业务单元仅可修改联系电话和备注。

### 部门

- 按业务单元、层级路径展示平铺列表，支持名称/编码搜索、组织及状态筛选。
- 新增、编辑、启停用、删除、CSV 导出；层级路径中的部门可点击筛选本部门及下级。
- 同一组织内编码唯一、同级名称不重名、上级只能选同组织启用部门，最多五级。
- 编辑不允许直接变更编码、所属组织或上级，避免隐式移动整个部门。
- 负责人选择本部门及下级的在职人员，支持编制、排序、备注。
- 停用检查本部门及下级在职人数，删除检查任何状态的人员和子部门。
- 点击在职人数进入人员页并选中对应部门。

### 人员与账号

- 左侧按当前所属组织展示业务单元、部门、子部门，支持搜索，节点显示在职人数。
- **2026-11-09 修复：** 人员左侧目录原来只能筛选、无法折叠，现为有下级的组织及部门增加独立展开/收起箭头，叶子节点不显示箭头；点击名称继续筛选人员，折叠不改变右侧当前人员结果。
- 默认展开当前所属组织的第一层，提供“全部展开 / 全部收起”，按账号、租户与所属组织分别记忆当前标签页会话的展开状态；从部门人数跳入人员页时自动展开所选部门的完整祖先路径。
- 搜索时保留祖先路径并自动展开匹配分支，支持继续手动折叠；清空搜索恢复搜索前的展开状态，无匹配时显示空提示。目录仍只使用当前权限范围内的组织、部门和人员。
- 默认显示可见组织范围内全部人员；选择组织展示其本级及下级，选择部门展示本部门及全部下级部门。
- 姓名、工号、邮箱、手机号搜索及账号状态筛选；支持 CSV 导出。
- 新增、编辑、组织/部门调岗、管理员/成员角色配置、邮箱及手机号登录账号维护、启停用、重置密码。
- 自动生成唯一工号；部门必须属于所选启用组织，且部门及所有上级部门均启用。
- 手机号按 +63 后 10 位或 09 开头 11 位校验。登录邮箱全局唯一；手机号也可用于登录。
- 新账号设初始临时密码；重置时生成随机临时密码，仅一次展示，不写入操作日志。密码用独立随机盐的 PBKDF2 摘要保存。
- 新账号或重置后的账号登录后必须先修改密码，修改完成前不渲染业务工作台。新密码不得与原密码相同。
- 重置密码使旧密码及旧会话失效；禁用账号后拒绝登录，已打开的标签页收到更新后退出。
- 当前登录人不能停用自己、重置自己的密码，或更改自己的组织、管理角色、登录邮箱；可通过“账号信息 → 修改密码”自助改密。
- 多租户共用的是同一登录身份，禁用及重置密码影响该登录身份的所有会话；暂不支持从单一租户修改多租户账号的登录邮箱，避免其他成员身份断链。
- 新增、编辑、状态变更、删除、密码重置、导出写入组织架构操作记录，仅显示当前可见范围内的记录。

## 建议产品验收顺序

1. 直接体验总部演示，确认左侧三个菜单可进入，业务单元能展开四层。
2. 退出并分别登录事业部、大区、经销商账号，核对上表人数及组织数，尤其检查看不到上级、其他事业部/大区、兄弟经销商。
3. 在人员页确认默认全部人员。点击组织或部门左侧箭头验证逐级展开/收起；点击“全部展开 / 全部收起”验证批量操作。点击“销售部”名称仍包含“渠道一组”的人员；点击“综合管理部”只显示该部门人员。搜索深层组织/部门时应自动展开祖先路径，清空后恢复之前的折叠状态；切换租户后展开状态独立。
4. 回到总部账号，切到海岛食品租户，确认组织、部门、人员、表单选择项和操作记录均切换，原租户数据不混入；刷新后仍在所选租户。
5. 在有权限的业务单元新增部门、再新增测试人员；用该账号登录，完成首次改密；再由管理员停用或重置密码，检查旧密码和旧会话失效。
6. 新建下级组织时验证不能跳级，点击经销商的新增下级按钮应不可用；删除有人员的部门应被阻止。
7. 搜索后导出，检查只有当前租户、当前组织范围及当前筛选结果；检查操作记录中没有明文密码。
8. 用下级账号或海岛租户直接打开旧订单页，确认没有展示总部旧示例数据。

## 尚未完成的原 PRD 能力及已知差异

本次目标是可操作的组织架构 Demo，以下不能视作正式生产能力或完整 PRD 验收通过：

- 未接服务端、数据库、真实多租户认证、独立租户管理、正式权限服务及并发事务；本地数据可被浏览器使用者修改，不能用于真实组织数据。
- 角色目前只有组织管理员和成员，尚未接入完整多角色、按钮/字段/审批权限。成员在组织架构中只读；后续应与第 3.9 节的完整角色模型整合。
- 其他业务模块尚未完成组织外键、按组织过滤、按角色操作控制。当前通过限制旧示例的展示范围防止误展示，不代表订单/财务等已实现多租户查询。
- 业务单元负责人暂用姓名文本录入，用于解决新组织尚无人员时的创建流程；未实现“本级及下级人员选择”、负责人离职联动和双语名称录入。地址暂为完整文本，未拆分省市区街道；历史生效日期补录原因未独立校验。
- 业务单元整棵子树迁移、部门层级调整、批量导入、导入模板未实现；导出为 CSV。
- 业务单元业务引用为示例计数，未对接真实未完结订单；人员未交款、未完成拜访、离职转交、默认线路/车辆/车仓、财务经销商范围尚未联动。因此新增岗位暂只提供管理员、仓管、财务、其他，不开放必须绑定线路或车辆的岗位。
- 人员停用是账号禁用，未完成入离职生命周期、离职日期、锁定状态、连续五次密码错误自动锁定、头像及完整多角色配置。
- 组织架构新增页面目前以中文为主，保留全局主题及导航语言切换；新表单、操作记录等尚未完整英文化。
- 运行 `npm test`、`npm run lint`、`npm run build`；当前 49 项自动检查通过，包含范围模型、账号失效及页面渲染检查。当前 Work 设置禁用了自动浏览器操作，本次没有完成真实浏览器截图、视觉检查或端到端点击验收，需按上面的步骤在 Demo 中检查。

## 开发定位

- `src/lib/organization.ts`：组织、部门、人员、租户成员、范围和业务校验。
- `src/lib/organization-context.tsx`：最新权限复核、本地持久化、账号同步及操作日志。
- `src/lib/organization-accounts.ts`：初始演示人员账号的首次准备，不覆盖已编辑账号。
- `src/components/organization-page.tsx`：三个业务页面、表单及确认。
- `src/components/personnel-directory.tsx`：人员页的组织部门目录、折叠、搜索与选择。
- `src/components/password-change.tsx`：主动改密与首次强制改密。
- `tests/organization.test.mjs`、`tests/organization-pages.test.mjs`：范围、操作及页面验证。
