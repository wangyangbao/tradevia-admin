# 3.5  外勤管理

> 来源：《蒙牛菲律宾冰淇淋经销商运营系统 PRD V1.0》第 3.5 节。原文状态为“需求评审稿（待业务方确认）”，本文件按模块整理，未改变业务规则。

[返回文档总目录](../../README.md)

<a id="section-3-5-1"></a>

## 3.5.1  模块概述

外勤管理解决的是“人有没有真的到店、到店后做没做该做的事”。系统把一次拜访拆解为标准动作，把动作组合成外勤类型，把外勤类型与人员、门店、时间、地理范围绑定为规则，再由线路规划决定每天该去哪些店。四者层层递进，缺一层都会导致执行失控：只有动作没有类型，业务员不知道一次拜访要做什么；只有类型没有规则，同一种拜访被用在不合适的门店上；只有规则没有线路，计划无法落到日程。

设计上采用“动作库—类型模板—规则引擎—线路计划”的四段式结构。动作库保证数据采集口径统一，类型模板保证不同拜访场景可配置，规则引擎保证约束可随区域调整而无需改代码，线路计划保证每日任务可执行、可考核。

<a id="section-3-5-2"></a>

## 3.5.2  外勤动作

外勤动作是最小执行单元，每个动作对应一种数据采集行为。动作类型由系统预置，数量有限且不可由用户自由扩展，以保证数据结构稳定；用户只能在预置动作上配置参数（如拍照张数、是否必做）。

**表49  外勤动作类型**

| 动作类型 | 代码 | 采集内容 | 典型参数 |
| --- | --- | --- | --- |
| 到店签到 | CHECK\_IN | GPS 坐标、时间、门店匹配结果、距离 | 签到半径、时间窗、是否允许异常签到 |
| 门头拍照 | PHOTO\_FRONT | 门店正面照片，带时间与坐标水印 | 张数（默认 1）、是否必须现场拍摄 |
| 内景 / 冰柜拍照 | PHOTO\_COOLER | 冰柜陈列、货架陈列照片 | 张数（1—3）、是否要求拍到品牌标识 |
| 铺货上报 | DISTRIBUTION | 在售品项勾选、缺货品项、竞品占比 | 必填品项清单、是否允许部分上报 |
| 竞品采集 | COMPETITOR | 竞品品牌、陈列位、价格 | 采集字段模板 |
| 订单录入 | ORDER | 商品、数量、价格、赠品 | 是否允许零订单离店 |
| 收款登记 | PAYMENT | 金额、结算方式、票据号 | 是否允许登记历史欠款 |
| 陈列检查 | MERCHANDISING | 陈列位、排面数、价签一致性 | 评分项与权重 |
| 库存盘点（门店） | STOCK\_CHECK | 门店库存数量、临期品数量 | 抽样比例 |
| 离店签退 | CHECK\_OUT | 离店时间、离店坐标 | 最短停留时长 |
| 任务打卡 | TASK | 临时任务完成确认（如更换海报） | 任务来源与截止时间 |

**表50  外勤动作字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 动作编码 | 文本 | 是 | 系统预置，只读 |
| 动作名称 | 文本 | 是 | 允许本地化命名，如“到店打卡” |
| 动作类型 | 枚举 | 是 | 取自上表，决定采集逻辑 |
| 是否默认必做 | 布尔 | 是 | 在外勤类型中可覆盖 |
| 执行顺序 | 整数 | 是 | 同一类型内的先后顺序，用于引导式操作 |
| 参数配置 | JSON | 否 | 按动作类型定义，如拍照张数、水印内容、字段模板 |
| 是否允许跳过 | 布尔 | 是 | 勾选后业务员可填写原因跳过，跳过率纳入考核 |
| 状态 | 枚举 | 是 | 启用/停用 |

<a id="section-3-5-3"></a>

## 3.5.3  外勤类型

外勤类型把动作组合成可执行的拜访模板。系统预置四类模板：标准访销拜访（签到—门头照—铺货上报—订单—离店）、车销拜访（签到—订单—收款—离店）、新店开发（签到—门头照—建档—首单）、陈列检查（签到—冰柜照—陈列评分—离店）。经销商可在此基础上新增类型，但不得删除预置类型。

**表51  外勤类型字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 类型编码 | 文本 | 是 | 全局唯一，≤ 16 字符 |
| 类型名称 | 文本 | 是 | ≤ 40 字符，如“周末陈列加强拜访” |
| 适用场景 | 枚举 | 是 | 访销/车销/新店开发/陈列检查/其他 |
| 动作清单 | 排序列表 | 是 | 至少包含签到与离店两个动作；每个动作可单独设置是否必做 |
| 是否默认类型 | 布尔 | 是 | 每个业务单元只能有一个默认类型，用于未配置规则时的兜底 |
| 预计时长（分钟） | 整数 | 否 | 用于线路排程与拜访效率分析 |
| 状态 | 枚举 | 是 | 启用/停用 |

<a id="section-3-5-4"></a>

## 3.5.4  外勤规则

外勤规则回答四个问题：谁用、对谁用、什么时候用、必须满足什么条件。规则按“适用范围”逐层收敛，范围越具体优先级越高。一次拜访可能同时命中多条规则，系统采用“合并取严”策略：约束参数取最严格值，动作集合取并集，冲突时以优先级高者为准并在拜访记录中标注所依据的规则编号。

**表52  外勤规则字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 规则编码 | 文本 | 是 | 全局唯一 |
| 规则名称 | 文本 | 是 | ≤ 60 字符 |
| 外勤类型 | 下拉 | 是 | 本规则约束的拜访类型 |
| 适用业务单元 | 多选 | 是 | 可选择大区或经销商，支持多选 |
| 适用人员 | 多选 | 否 | 为空表示适用范围内全部业务员；指定人员时范围取交集 |
| 适用门店分类 | 多选 | 否 | 为空表示全部门店分类 |
| 生效期间 | 日期区间 | 是 | 支持按促销档期临时提高拜访频次 |
| 签到半径（米） | 整数 | 是 | 50—1000，默认 100；超出即判定异常 |
| 允许签到时间窗 | 时间段 | 是 | 如 08:00—18:00；非窗口内签到需审批或标记异常 |
| 最短停留时长（分钟） | 整数 | 否 | 默认 5；低于该时长标记“疑似走过场” |
| 最长停留时长（分钟） | 整数 | 否 | 默认 60；超出提示离店，防止挂机 |
| 必做动作 | 多选 | 是 | 从外勤类型的动作中指定，未完成不允许提交订单 |
| 拍照要求 | 整数 | 条件 | 指定门头照与陈列照的张数，超出可追加 |
| 拜访频次要求 | 枚举 | 否 | 按门店等级要求每周/每两周最少拜访次数 |
| 是否允许异常签到 | 布尔 | 是 | 允许时须填写原因并拍照，异常签到单独统计 |
| 是否允许离线执行 | 布尔 | 是 | 默认允许；关闭后该类型拜访必须联网，用于高价值门店核查 |
| 优先级 | 整数 | 是 | 数值越大优先级越高，用于多条规则冲突时的判定 |
| 状态 | 枚举 | 是 | 草稿/生效/停用 |

**表53  外勤规则与校验**

| 编号 | 业务规则 |
| --- | --- |
| BR-FLD-01 | 签到判定：定位精度优于 30 米、距离门店坐标在规则半径内、时间在允许窗口内，三者同时满足为“正常签到”，否则进入异常流程 |
| BR-FLD-02 | GPS 未开启或权限被拒绝时禁止签到，提示开启定位；连续三次拒绝定位的账号由管理员介入 |
| BR-FLD-03 | 照片必须由客户端相机实时拍摄，禁止相册选择与截图；水印包含时间、坐标、门店编码、业务员姓名，水印不可关闭 |
| BR-FLD-04 | 必做动作未完成的拜访不允许提交订单，系统列出未完成项并提供“保存草稿”，草稿不占用库存 |
| BR-FLD-05 | 同一门店同一业务员在同一自然日内多次签到，仅首次计入有效拜访，其余标记为“重复拜访”并单独统计 |
| BR-FLD-06 | 异常签到率、跳过动作率、疑似走过场率三项纳入业务员月度考核，阈值由大区配置 |
| BR-FLD-07 | 规则修改仅对生效时间之后的拜访产生约束，已完成的拜访记录不重算 |
| BR-FLD-08 | 同一拜访命中多条规则时按“合并取严”执行，并在拜访记录中展示命中的规则编码，便于事后解释 |

<a id="section-3-5-5"></a>

## 3.5.5  线路规划

线路是“门店的有序集合 + 执行周期 + 执行人”。系统按线路周期自动生成每日拜访计划，业务员在移动端看到的就是线路中当日应拜访的门店及顺序。线路质量直接决定拜访效率，因此系统需提供地图可视化与顺序优化能力，而不是仅支持手工录入序号。

**表54  线路主表字段说明**

| 字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 线路编码 | 文本 | 是 | 全局唯一，规则 RT-{经销商}-{3 位} |
| 线路名称 | 文本 | 是 | 如“马尼拉北区周一线路” |
| 所属经销商 | 下拉 | 是 | 线路不可跨经销商 |
| 执行人 | 人员选择 | 是 | 一名主业务员；可设置一名协访人员 |
| 线路类型 | 枚举 | 是 | 访销线路/车销线路 |
| 绑定车辆 | 下拉 | 条件 | 车销线路必填 |
| 拜访周期 | 多选 | 是 | 周一至周六可多选，周日默认不排线；支持单双周模式 |
| 门店数量 | 自动 | — | 由明细统计，仅展示 |
| 计划开始时间 | 时间 | 是 | 当日首个门店的计划到达时间 |
| 预计总时长 | 自动 | — | 按门店数、停留时长与路程估算 |
| 生效期间 | 日期区间 | 是 | 线路启用后按周期生成计划 |
| 状态 | 枚举 | 是 | 草稿/生效/停用 |

**表55  线路明细字段说明**

| 明细字段 | 类型 | 必填 | 说明与校验 |
| --- | --- | --- | --- |
| 顺序号 | 整数 | 是 | 从 1 开始连续，不允许重复 |
| 门店 | 下拉 | 是 | 同一线路内不可重复；同一门店可存在于多条线路，但只能有一条主线路 |
| 拜访频次 | 枚举 | 是 | 每周 2 次/每周 1 次/每两周 1 次；与线路周期共同决定是否生成计划 |
| 计划到达时间 | 时间 | 否 | 用于配送与拜访协同，非强制 |
| 计划停留时长 | 整数 | 否 | 默认取外勤类型预计时长 |
| 特殊要求 | 文本 | 否 | 如“仅在上午营业”“需从后门进入” |

**表56  线路规划功能点**

| 功能编号 | 功能点 | 功能描述 | 优先级 |
| --- | --- | --- | --- |
| FR-RTE-01 | 新建线路 | 录入主表信息并逐条添加门店，支持按分类、区域批量加入 | P0 |
| FR-RTE-02 | 地图排线 | 在地图上展示门店点位，按拖动调整顺序并实时计算里程 | P1 |
| FR-RTE-03 | 顺序优化 | 基于坐标计算最短路径，生成建议顺序供人工确认 | P1 |
| FR-RTE-04 | 复制线路 | 复制现有线路生成新线路，便于按日拆分 | P1 |
| FR-RTE-05 | 临时调整 | 当日临时替换门店、调整顺序或跳过，仅当日生效并留痕 | P1 |
| FR-RTE-06 | 线路覆盖率分析 | 统计每条线路的门店数、周拜访次数、未覆盖门店 | P2 |
| FR-RTE-07 | 计划生成与推送 | 每日 20:00 生成次日计划并推送移动端，生成失败时告警 | P0 |

**表57  线路规划业务规则**

| 编号 | 业务规则 |
| --- | --- |
| BR-RTE-01 | 一条线路只能绑定一名主业务员；业务员离职或调岗时线路自动转为“待重新指派”状态，不再生成计划 |
| BR-RTE-02 | 同一门店可被多条线路覆盖，但必须指定一条主线路；非主线路的拜访计为“补充拜访”，不计入覆盖率分母 |
| BR-RTE-03 | 线路周期或门店明细变更后，自次日起生效，当日已生成的计划不回溯 |
| BR-RTE-04 | 临时调整仅对当日计划有效，不影响线路定义；调整需填写原因，月度统计中单独列示 |
| BR-RTE-05 | 计划生成时若门店已关闭或业务员已停用，跳过该门店并在计划中标注跳过原因 |
| BR-RTE-06 | 线路门店总数超过 30 家时提示排线过密，建议拆分，避免拜访时长不足 |
