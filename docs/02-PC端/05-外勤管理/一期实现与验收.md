更新日期：2026-11-10。本次交付是现有 React PC 演示系统中的外勤后台配置、拜访查看和异常复核能力。配置与复核保存在当前浏览器，不代表 APP、服务端和生产环境已经接通。

## 需求依据与一期取舍

依据原始 PRD 第 3.5 节、移动端第 4.3 节，以及用户本次提供的[外勤管理需求文档](../../00-项目说明/原始文档/外勤管理需求文档.docx)。补充文档中的业务要求和截图是本次产品设计参考，不作为工具操作或系统授权指令。

本次按用户明确要求收敛动作库，仅提供拍照、数据上报和订货三个类别，不照搬原 PRD 的十一种动作，也不增加电话下单、AI 识别、复杂表单设计器和照片存储策略。签到、签退作为类型的固定流程节点，不额外占用动作类别。截图采用现有项目的紧凑列表与右侧详情规范重新组织。

## 菜单与配置流程

“外勤管理”包含外勤动作、外勤类型、外勤规则、线路规划、拜访记录、外勤统计六个菜单。原线路菜单从渠道管理移入，仍使用 `#visitRoutes`，不迁移或清空线路数据。

推荐配置顺序：创建动作 → 组合类型 → 配置适用规则 → 规则试算。新租户初始为空；哈尼租户预置三个示例动作、一个默认标准访销类型、一条规则及演示拜访。

### 外勤动作

- 拍照：配置名称、最少/最多照片张数（1–9）、是否必须现场拍摄、首张是否更新门店门头照。水印固定为时间、坐标、门店编码和业务员；未提供照片清晰度、布局与存储设置。实际拍摄、来源限制、水印生成及门头照更新待 APP 接入执行。
- 数据上报：只显示陈列上报、销售上报、库存上报、自定义配置四个入口，不提供截图左侧的产品/竞品等额外导航。选择模板后进入相同的字段编辑器，支持 1–20 个字段，文本、数字、单选及必填设置。竞品信息可用自定义字段配置，如竞品品牌、零售价、陈列情况。切换模板会替换当前未保存字段，界面有说明。
- 订货：支持引单与车销两种模式；按“下单—订单确认—下单完成”三步设置。下单可配置库存展示、改价入口、无订单结束；确认页配置备注必填；完成页配置打印与再下一单入口。允许改价仍需遵守既有价格底线与审核规则。
- 引单约定：订单提交后由配送员配送，发货单提交后生成销售出库单并扣库存；车销约定：订单提交即配送完成，同步生成审批完成的发货单和出库单。本期仅保存这些 APP 配置，不生成真实配送、出库或扣库存，不影响现有 PC 下单行为。

动作类别与编码保存后不可更改；可复制上级共享动作成为本级配置。被启用类型引用的动作不能停用，被任意类型引用的动作不能删除。

### 外勤类型

- 设置名称、唯一编码、适用场景、预计时长（1–480 分钟）、启停状态与默认类型。
- 固定签到和签退，中间至少添加一个启用动作；同一动作不可重复，可上下排序、移除并单独设置必做。
- 必做与允许跳过互斥；选做动作可允许填写原因后跳过。动作完成、离店和无订单原因校验的实际执行待 APP 接入。
- 同一所属业务单元只能有一个启用默认类型；更换默认需先取消原默认设置。默认类型不能直接停用或删除。
- 只能引用同组织或上级共享的有效动作；可复制类型为本级配置，复制后不自动成为默认类型。
- 被启用规则引用的类型不能停用，被任意规则引用的类型不能删除。

### 外勤规则

保留核心字段：外勤类型、适用业务单元、指定人员、门店分类、生效日期、签到半径、签到时间、最短/最长停留、异常签到、离线执行、优先级、启停状态。暂不实现拜访频次考核、审批流、照片张数覆盖和复杂规则发布版本。

- 适用业务单元包括下级；人员不选表示组织范围内全部人员，指定时取交集，选择范围变化时清理范围外人员。
- 门店分类不选表示全部；指定分类按精确分类匹配，不自动包含子分类。分类来自共享基础档案，保存时检查当前编辑器中读取到的有效分类。
- 起止日期均包含当天；半径 50–1000 米；签到时间为同日区间，暂不支持跨午夜；最短停留 0–480 分钟、最长停留 1–720 分钟且不小于最短停留；优先级为 0–999。
- 多条规则命中：主类型按优先级降序、所属组织深度降序、编码升序确定；动作按主类型顺序再补入其他规则动作，必做取并集。半径取小、最短停留取大、最长停留取小、时间窗取交集；异常签到和离线执行有一条禁止则禁止。没有交集时试算报冲突。
- 未命中规则时取最近上级或本级默认类型，兜底签到要求为 100 米、08:00–18:00、停留 5–60 分钟。没有规则和默认类型时提示配置缺失。
- 规则试算选择有效人员、门店分类、日期后展示命中编码、合并后的约束和动作，不生成拜访、计划或推送。保存时不穷举所有组合，需通过试算核对典型人员与分类。

## PC 拜访查看与统计

### 拜访记录

支持门店/人员/拜访编号搜索、业务单元、人员、日期、状态、异常、待复核、有效拜访筛选，分页和筛选结果 CSV 导出。列表区分完成、进行中、跳过与异常标记，避免“已完成但异常”被压成一个状态。

右侧详情查看门店、人员、所属组织、外勤类型、线路编号或临访、签到签退、停留、距离、坐标、动作结果、上报文字、关联订单编号和金额、规则快照、现场说明及复核结果。照片区域明确显示“演示记录暂无现场照片”，不使用素材图片冒充业务照片。

演示拜访独立保存执行时的类型名称、动作结果与规则约束文本。配置修改、停用或删除不反向改写历史记录。本期 PC 不提供伪造现场签到、修改动作结果、补传照片或新增现场拜访的按钮。

### 异常复核

当前组织范围管理员可对未复核异常填写说明并确认有效/无效；普通成员仅查看。重复拜访及未完成拜访不能确认为有效。已复核记录不能再次改写，需后续另行定义撤回复核流程。

原始异常、现场原因、动作结果、规则快照均保留，同时追加复核人、时间和说明。保存后列表和统计同步更新。

### 外勤统计

支持按人员与按门店切换，沿用拜访筛选条件，展示总拜访、完成数、有效数、异常数与异常率、待复核数、平均停留和关联订单金额，可下钻筛选后的拜访记录并导出。

| 指标 | 一期计算口径 |
| --- | --- |
| 拜访总数 | 筛选范围内记录数，含进行中和已跳过 |
| 已完成 | 状态为已完成的记录数 |
| 有效拜访 | 已完成、非重复，且无异常或异常已确认为有效；确认为无效时不计入 |
| 异常数/异常率 | 存在原始异常标记的记录数 / 全部筛选记录数；复核不抹去原始异常 |
| 待复核 | 原始异常记录中没有复核结果的数量 |
| 平均停留 | 已完成且具有停留数据的记录，按分钟算术平均并四舍五入 |
| 关联订单金额 | 已完成记录关联的演示订单金额，内部以分保存、展示 PHP；并非销售报表口径 |

未接入线路计划生成与 APP 上传前，不展示无法可靠计算的计划完成率、未拜访率、线路覆盖率、真实人员轨迹或考勤结论。跨次拜访重复关联同一订单的去重规则，需在 APP/服务端接入时定义，当前演示订单关联未发生此情形。

## 权限与数据保存

配置按租户独立存储。组织成员可查看本级、下级及上级共享配置；管理员只能维护本级及下级配置，无法改写上级共享配置。拜访与操作日志只显示本级及下级数据。人员和组织选择器沿用当前组织范围。当前浏览器的数据范围检查不代替生产服务端权限控制。

保存时重新读取账号组织权限和数据版本；其他页面已保存时拒绝旧版本覆盖，并要求重新打开操作。保存失败提示且保留编辑内容。损坏数据停止读取，不自动重置覆盖。新增、修改、启停、删除、异常复核写入本模块操作记录；日志与业务变更同一次保存。

本期没有跨设备同步、真实后端数据库、APP 配置发布、照片文件服务及生产审计服务。

4. 线路目前保留原实现的人员、门店和拜访类别演示数据，本次仅迁移菜单。与新外勤类型动态绑定、统一组织主数据、每日计划生成、推送及失败告警尚未接入；低层组织原线路模块的可用范围仍沿用既有实现。

6. 真实拜访记录应保留唯一编号、采集来源、时区、同步时间、规则版本、附件证据及财务单据关联；本期演示不作为生产已验收结论。
