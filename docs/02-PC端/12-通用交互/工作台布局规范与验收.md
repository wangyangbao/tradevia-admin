# 工作台列表布局优化与验收

更新时间：2026-11-09。依据产品反馈及提供的纷享销客截图，优化页面空间利用和各菜单查询、按钮布局；本记录补充原 PRD，不修改权限和业务规则。

## 发现的问题

- 人员等组织架构页面同时展示大标题、说明文案、大块组织范围提示及三张统计卡片，列表与组织树被推到下方。
- 原有业务列表也存在独立页头、统计卡片、列表内重复标题，区域筛选与搜索分散。
- 新增、导出、查询重置在不同页面位置不一致，切换菜单后需要重新寻找。
- 经销商以大卡片展示，不便于在同屏比较多家经销商。

## 采用的布局规则

1. **紧凑页头**：标题靠左，必要上下文随标题显示；新增等主操作在右侧，导出、操作记录等次操作相邻，采用统一按钮高度和间距。
2. **组织范围随标题显示**：显示当前所属组织和“仅本级及下级组织”，租户及角色可从左上角工作空间和组织名称提示查看，取消独立的大块权限提示。
3. **统计转为一行摘要**：保留组织数、部门数、人员数及业务列表原有汇总，不再以大卡片占据列表上方空间；摘要和筛选结果各自保留原有统计口径。
4. **查询条件集中**：搜索、所属大区/业务单元、状态等条件统一放在表格上方左侧；清除筛选及全部展开等辅助操作放右侧。保持输入或选择即生效，不新增没有必要的确认步骤。
5. **列表优先**：桌面端用剩余视口高度展示组织树和表格，内容较多时分别滚动；表头在滚动区域内固定，底部保留数量与范围提示。双行人员信息仍显示姓名/工号、组织/部门、邮箱/手机号等核心字段。
6. **窄屏适配**：按钮和筛选项自动换行，人员目录移至列表上方；表格横向滚动以保留字段，不用隐藏关键数据换空间。
7. **功能边界清晰**：参考截图的密度和操作位置，保留当前系统主题；没有实现的导入、分页等能力不添加假按钮。

## 数据与权限约束

- 仅改展示布局和查询条件位置，不改变租户成员身份、组织范围、角色、账户及已保存业务数据。
- 人员选择组织或部门仍筛选本节点及下级，折叠只改变目录展示。
- 导出继续受当前权限与筛选条件限制。
- 未接入组织归属的旧业务示例仍只向哈尼租户总部成员展示。
- 一键清除查询会恢复搜索词、状态及所属大区等条件为默认值。

## 验收建议

1. 打开人员页：确认只有一处页面标题，顶部不再有独立大权限提示和三张统计卡片，组织树与人员列表更靠上。
2. 在桌面窗口滚动人员列表与组织树：确认查询区域、表头、底部数量提示可用，两个内容区域互不影响。
3. 选择部门、展开/收起节点、搜索部门，确认原筛选逻辑及展开状态记忆不变。
4. 在业务单元、部门及各业务列表检查右上方操作按钮、左侧集中查询条件和右侧清除筛选的布局。
5. 订单页应只出现一个新建入口；新增订单后依然出现在订单列表，详情与导出可用。
6. 经销商页为表格，点击详情能查看原有负责人、门店数与销售额；更换大区或搜索时，结果和汇总随之变化。
7. 拜访路线检查状态、地区、执行人及周期组合筛选，保留地图分配入口及原有操作。
8. 切换深浅主题与缩小窗口，确认按钮换行、目录与表格滚动可用；下级账号仍不能看到上级/兄弟组织。
