## 5.1  性能需求

性能指标按规划规模设定：四十余家经销商、约一万至两万家门店、约三百名业务员、日均三千至五千张订单。下表指标为验收基线，测试环境需按此规模构造数据，不得用百条数据测试后宣称达标。

**表105  性能指标要求**

| 指标 | 要求 | 测试条件 |
| --- | --- | --- |
| 页面响应 | 列表查询 ≤ 2 秒，表单保存 ≤ 1 秒，详情页打开 ≤ 1.5 秒 | 数据量 10 万行以内，网络延迟 50ms |
| 并发能力 | 支持 300 个并发在线用户，峰值 50 TPS 的订单提交 | 压测持续 30 分钟，错误率 ≤ 0.1% |
| 报表性能 | 百万行明细聚合查询 ≤ 5 秒，复杂交叉报表 ≤ 10 秒 | 按月度全量数据测试 |
| 批量导入 | 1 万行门店或商品导入 ≤ 3 分钟 | 含校验与错误输出 |
| 移动端启动 | 冷启动 ≤ 3 秒，热启动 ≤ 1 秒 | 中端安卓设备（4GB 内存） |
| 离线开单 | 单笔开单保存 ≤ 300 毫秒 | 本地数据库 5000 条门店、2000 条商品 |
| 同步性能 | 1000 条离线记录上传 ≤ 60 秒 | 4G 网络，照片不含在内 |
| 文件上传 | 单张 5MB 照片上传 ≤ 5 秒 | 4G 网络 |

系统需具备横向扩展能力：应用层无状态部署，可通过增加节点线性提升并发；报表查询走独立分析库，不与业务事务争抢资源；文件与照片存储独立于数据库，避免大对象拖慢查询。当日订单峰值集中在上午 9 点至 11 点与下午 2 点至 4 点，容量规划需按峰值而非均值设计。

<a id="section-5-2"></a>

## 5.2  易用性需求

一线业务员的数字素养差异较大，部分人员首次使用智能手机作业。易用性要求不是“界面好看”，而是“无需培训即可完成核心动作”。因此需满足：单次拜访的核心操作不超过 6 步；关键按钮固定在屏幕底部单手可达区域；所有失败提示必须说明“为什么失败”与“怎么做”。

**表106  易用性标准**

| 要求 | 具体标准 |
| --- | --- |
| 操作步数 | 一次标准拜访从签到到离店 ≤ 6 个主要页面跳转；开单 ≤ 4 步 |
| 信息层级 | 每个页面只有一个主行动按钮，次要操作收纳在“更多”菜单 |
| 输入效率 | 默认值与历史值优先填充；数字键盘优先；避免自由文本，能用选择就不用输入 |
| 容错 | 危险操作二次确认；误操作可撤回（限审核前）；断网不丢已填内容 |
| 反馈 | 每个操作 200 毫秒内有视觉反馈；耗时操作显示进度；成功与失败均有明确文案 |
| 可读性 | 正文不小于 14pt，关键数字不小于 20pt；对比度符合无障碍要求；强光下可读 |
| 一致性 | 同一业务对象在不同页面的字段名称、单位、颜色保持一致 |
| 帮助 | 首次使用的关键页面提供 3 步引导；常见问题内嵌帮助入口，不依赖纸质手册 |

<a id="section-5-3"></a>

## 5.3  可维护性需求

系统的可维护性取决于三件事：配置是否外置、日志是否充分、变更是否可回滚。业务规则（签到半径、审批阈值、信用控制方式、拜访频次）必须通过配置实现，不得硬编码在代码中，否则每次区域政策调整都需要发版。

**表107  可维护性要求**

| 要求 | 说明 |
| --- | --- |
| 配置化 | 外勤规则、审批流、信用控制、价格策略、预警阈值均可在界面配置并即时生效 |
| 参数分级 | 配置分总部级、事业部级、经销商级三层，下级默认继承上级，可覆盖但不可突破上级红线 |
| 日志完备 | 接口调用、定时任务、规则命中、异常堆栈均记录可检索日志，保留不少于 90 天 |
| 监控告警 | 核心接口成功率、任务执行状态、数据库连接、磁盘使用率纳入监控，异常 5 分钟内告警 |
| 灰度与回滚 | 功能发布支持按业务单元灰度；配置变更保留历史版本，可一键回滚 |
| 数据修复 | 提供受控的数据修复工具，所有修复操作需审批并记录修复前后差异 |
| 文档 | 接口文档、配置手册、运维手册与版本同步更新，不滞后于发布 |

<a id="section-5-4"></a>

## 5.4  可扩展性需求

业务扩展的三个可预期方向是：经销商数量增长、渠道类型增加、与其他系统的集成增多。系统需在不改表结构、不改核心代码的前提下支撑这三类扩展。

**表108  可扩展性要求**

| 维度 | 扩展要求 |
| --- | --- |
| 组织扩展 | 新增经销商只需在业务单元中建节点并挂接上级，权限与数据范围自动继承，无需改配置 |
| 商品扩展 | 新增品牌、品类、SKU 通过主数据维护完成，报表维度自动纳入，不需要新增报表 |
| 渠道扩展 | 新增渠道类型时通过渠道主数据与价目表组合实现，不修改订单逻辑 |
| 规则扩展 | 外勤动作类型预留扩展位，新增动作只需开发采集组件，不影响既有拜访流程 |
| 接口扩展 | 接口层采用适配器模式，新增外部系统只需新增适配器，不修改业务服务 |
| 多语言扩展 | 文案资源外置，新增语言只需增加语言包，不改代码 |
| 多币种扩展 | 新增币种通过币种表与汇率配置完成，报表按本位币折算 |
| 部署扩展 | 支持单经销商独立部署与多经销商共享部署两种模式，数据隔离通过组织路径实现 |

<a id="section-5-5"></a>

## 5.5  安全与合规需求

系统承载门店信息、人员信息与资金数据，安全要求覆盖传输、存储、访问、审计四个层面。涉及个人信息的字段（手机号、身份证号、银行账号）需按最小必要原则采集，并在展示时脱敏。

**表109  安全与合规要求**

| 层面 | 要求 |
| --- | --- |
| 传输安全 | 全站 HTTPS，禁用弱加密套件；移动端与接口均校验证书，禁止降级 |
| 存储安全 | 密码加盐哈希存储；敏感字段加密存储；本地数据库加密；备份文件加密 |
| 访问控制 | 基于角色的访问控制 + 组织数据权限；敏感操作二次认证；会话超时 30 分钟 |
| 审计 | 登录、权限变更、导出、删除、改价、退款六类操作强制留痕，日志不可篡改 |
| 合规 | 个人信息采集告知与同意；数据出境遵循当地法规；票据与税务要素按当地要求配置 |
| 容灾 | 数据库每日全量备份 + 增量备份，保留 30 天；RPO ≤ 15 分钟，RTO ≤ 4 小时 |
| 终端安全 | 移动端设备丢失可远程解绑并擦除本地数据；越狱或 Root 设备登录时提示风险 |

## 5.6  兼容性与部署环境

**表110  兼容性与部署要求**

| 项目 | 要求 |
| --- | --- |
| 浏览器 | Chrome 90+、Edge 90+；不支持 IE；分辨率 1366×768 及以上 |
| 移动端 | Android 8.0+、iOS 13+；主流品牌机型；不承诺对定制 ROM 的完全兼容 |
| 打印 | 支持 A4 激光打印与 58mm/80mm 热敏打印；打印模板可配置 |
| 部署 | 支持公有云与私有云部署；数据库与应用可分离部署；支持容器化 |
| 时区 | 服务端统一 Asia/Manila（UTC+8），客户端按设备时区展示但业务时间以服务端为准 |
